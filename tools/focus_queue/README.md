# ES focus queue

Lets the player queue national focuses. Russian version: README_ru.md. Ported from the FFU focus queue (workshop 3106240385, used with the author's permission) and extended for ES.

## How it works
- `gain_focus` (common/modifiers/00_static_modifiers.txt) carries `es_fq_active_marker = 1`, so `es_fq_idle` can tell when no focus is running.
- Once a day, `on_daily` runs `es_fq_daily_update` for every human country. When idle, `es_fq_tick` walks the queue:
  - It drops entries that are completed, mutually excluded, or no longer in the country's tree.
  - It skips entries whose requirements are unmet. They turn red and stay queued.
  - It starts the first startable entry with `load_oob = es_focus_queue/<id>` (`history/units/es_focus_queue/<id>.txt` contains `focus = { current = <FOCUS> }`).
- "Auto" focuses whose `available` uses `*_auto_focus_only_tt` (Nabiullina economy, UKR timed focuses, NTO refugees, WGN march), and focuses whose `available` is always `always = no`, are never queueable. Their event chains keep running in parallel with the queue.

## After changing any focus tree
```
python tools/focus_queue/generate.py
```
Then check `report.txt`, especially the "Kept but REVIEW" list and any warnings.

Every `mark_focus_tree_layout_dirty = yes` should be followed by `add_to_variable = { es_fq_ui_revision = 1 }`. The report lists any call that is missing it. While `TREE_GUI_DIRTY = False` (the default), the tree buttons refresh every tick anyway. The line only matters if you switch that setting on.

`focus_ids.json` keeps every focus id stable so saved queues survive updates. Commit it, and never renumber it.

## Adding new focuses, branches or trees
Nothing is registered by hand. Write the focuses normally in `common/national_focus/`, then run the generator.
- **New focuses or a new branch:** each new focus gets the next free id. Existing ids never change, so saved queues stay valid.
- **A new focus tree:** picked up automatically, including its `es_fq_supported` entry, its button overlay and its shared focuses.
- **Branches hidden by `allow_branch`:** the buttons follow the same condition. If something reveals the branch, put `add_to_variable = { es_fq_ui_revision = 1 }` after `mark_focus_tree_layout_dirty = yes`; the report flags any that are missing.
- **Script-driven ("auto") focuses:** give `available` a `custom_override_tooltip` with a `*_auto_focus_only_tt` key and `always = no`, as the Nabiullina, UKR, NTO and WGN ones do, and they are left out of the queue. A plain top-level `always = no` is left out too.
- **Removed or renamed focuses:** the old id stays reserved. Queues in saves drop it automatically.
- **Conditional `offset` blocks:** handled, with one button per layout variant, but they're capped at 4 conditional offsets per focus chain.

## Refresh behaviour
- Tree buttons have no `dirty`. The engine re-evaluates them every tick while the focus view is open, so they are correct from the first hour of the game. Set `TREE_GUI_DIRTY = True` in `generate.py` only if the focus screen gets slow; buttons then refresh at the daily tick, on queue clicks, and on `mark_focus_tree_layout_dirty`.
- The queue panel keeps `dirty = es_fq_ui_revision`. Opening it always bumps the variable, so it is evaluated immediately.

## Calibration
If the tree buttons sit off their focuses, adjust `TREE_ORIGIN_X/Y`, `FOCUS_STEP_X/Y` and `TEXT_OFFSET_*`, `TEXT_FONT` at the top of `generate.py`, then re-run it. If the open button overlaps something, its position is set in `interface/es_focus_queue.gui` (`es_fq_open_window`).
