# «Фламинго»: игровая 3D-модель

Новая низкополигональная модель, построенная по четырём изображениям,
предоставленным пользователем 12 сентября 2026 года. Геометрия создана
программно с нуля; исходный 3D-файл модели с изображений не использовался.
Пропорции подобраны визуально, это не инженерная реконструкция.

Воссозданы длинный тёмный корпус, носовой обтекатель со штангой, прямые
крылья, верхняя мотогондола на обтекателе, углублённый воздухозаборник
с декоративным вентилятором, светлое сопло, четыре хвостовых стабилизатора,
длинные направляющие, швы, заклёпки и небольшие светлые метки.

## Файлы и подключение

- `gfx/models/units/missiles/flamingo/flamingo.mesh`: 3 760 треугольников,
  11 280 вершин, один материал, одна кость `root`.
- `flamingo_diffuse.dds`, `flamingo_normal.dds`, `flamingo_specular.dds`:
  материалы 512 × 512 с полной цепочкой из 10 mip-уровней.
- `flamingo_idle.anim`: статическая поза, привязанная к `root`.
- `gfx/entities/ukr_flamingo.gfx` и `.asset`: регистрация mesh и entity.
- `common/units/equipment/ES_guided_missiles.txt`: только у оборудования
  `ukr_light_guided_missile_flamingo` изменён `sprite` на `ukr_flamingo`.

Остальные ракеты, характеристики и технологии не меняются. Новая entity самостоятельна: содержит собственные состояния `idle`,
`launch`, `move`, `bomb`, `crash`, `explode`, свой mesh и масштаб 0.55.
Начальное состояние — `idle`, после `launch` выполняется переход в `idle`. Ось вверх — Y, нос направлен по −Z,
как у существующей модели «Точки» в моде. Общая видимая длина выбрана
сопоставимой с предыдущей моделью. Точка `engine_exhaust` находится
у сопла верхнего двигателя. Движение задаёт игра; отдельная анимация
подвижных частей или взлёта для этой жёсткой модели не создавалась.

## Исходник и сборка

`flamingo.obj`, `flamingo.mtl`, `flamingo_diffuse.png` можно импортировать
в Blender или другой 3D-редактор. Детали разделены на именованные группы.
OBJ — статический обменный формат; игровой скелет содержится в `.mesh`.

Из корня мода, Python 3 с NumPy и Pillow:

```powershell
python tools/flamingo/build.py
python tools/flamingo/render.py
python tools/flamingo/validate.py
```

Сборка воспроизводит mesh, материалы, анимацию и OBJ. Скрипт проверки
сравнивает изменение файла оборудования с текущим HEAD; после коммита
этой работы этот конкретный контроль нужно сравнивать с прежним коммитом.

## Проверка

`preview.png` и `views.png` — рендеры экспортированного mesh с его
diffuse-текстурой. Они показывают фактическую геометрию, но не являются
скриншотами HOI4 и не воспроизводят её шейдер в точности.

Проверены индексы и ориентация треугольников, нормали и тангенты, UV,
веса и кость, структура анимации, материалы и mip-уровни, уникальность
новых имён и изменение только нужного sprite. Проверка в запущенной
HOI4 не проводилась. В игре следует проверить отображение «Фламинго»,
направление полёта, масштаб, выхлоп и отсутствие ошибок загрузки ассетов.

## Исправление невидимой модели

В журнале HOI4 от 12 сентября 2026 года подтверждена ошибка:
`Couldn't find parent clone entity missile_default_entity` для
`gfx/entities/ukr_flamingo.asset`. Зависимость от этой entity удалена.
Проверка контролирует отсутствие зависимости, наличие состояний и
привязку всех их анимаций. Полёт после исправления ещё не проверен
в запущенной игре; для проверки нужен полный перезапуск HOI4.
